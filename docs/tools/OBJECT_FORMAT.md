# RISC-VM 재배치 오브젝트 (legacy `CVMOBJ2` v2)

`vmasm -c`가 만드는 `.o`는 소스 문자열 묶음이 아니라 little-endian 바이너리
오브젝트다. 파일 magic은 `CVMOBJ2\0`, 버전은 2다.

오브젝트에는 다음 정보가 들어간다.

- `.text`, `.rodata`, `.data`의 실제 기계어/데이터 바이트
- 파일 바이트 없이 메모리 크기만 갖는 `.bss`
- 각 심볼의 섹션 인덱스와 섹션 상대 값
- 전역/외부/엔트리 속성
- weak/common 및 function/object 타입, 심볼 크기
- 재배치 대상 섹션, 바이트 오프셋, 심볼, addend

지원 재배치는 다음 세 가지다.

| 종류 | 계산식 | 용도 |
|---|---|---|
| `ABS32` | `S + A` | 32비트 절대 주소/값 |
| `ABS64` | `S + A` | 64비트 절대 주소/값 |
| `REL32` | `S + A - (P + 4)` | 32비트 PC-relative 분기/호출 |

`S`는 최종 심볼 주소, `A`는 오브젝트에 기록된 signed addend, `P`는 재배치
필드의 최종 주소다. 링커는 `ABS32` 범위와 `REL32` signed 범위를 검사하며
넘치면 조용히 자르지 않고 링크를 실패시킨다.

현재 재배치 표현식은 `symbol + constant` 형태의 선형식만 허용한다. 괄호와
상수의 덧셈/뺄셈은 가능하지만 심볼 곱셈, 비트 연산, 음의 심볼 계수와 `$`는
거부한다. `.byte`와 `.word`에는 재배치를 만들지 않으며 심볼 주소는
`.dword` 또는 `.qword`로 저장해야 한다.

심볼 해석 우선순위는 strong 정의, common, weak 정의 순서다. 여러 common은
최대 크기·최대 정렬로 `.bss`에 한 번 할당하고, 미해결 weak 참조는 0으로
해석한다. 여러 strong 정의는 오류이며 여러 weak 정의만 있으면 입력 순서상
첫 정의를 사용한다.

`cvmlink`는 입력 오브젝트의 같은 이름 섹션을 합치고 각 출력 섹션을 4KiB
경계에 배치한다. 로컬 심볼은 입력 파일 안에서만 보이고 `.global` 정의만 다른
오브젝트의 `.extern`을 해결한다. 중복 전역, 미해결 심볼, 재배치 overflow,
실행 섹션이 아닌 entry는 오류다. 결과는 RX/R/RW/RW-BSS의 `RVMEXF01`
다중 세그먼트 이미지다.
